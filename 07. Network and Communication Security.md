# Network and Communication Security

---

## Overview

_Volatile facts (framework versions, requirement numbers, reporting clocks) are maintained in [note 00](00.%20Current%20Versions%20and%20Facts.md). Check it before relying on figures here._

Network and communication security covers the controls, architecture decisions, and operational practices that protect data as it moves across and between systems — and protect the infrastructure that carries it. This includes physical networks, wireless, virtual networks, cloud connectivity, and the protocols underpinning all of it.

In Australia, this domain intersects directly with mandatory regulatory obligations. Federal government entities operate under the Protective Security Policy Framework (PSPF) and the ASD Information Security Manual (ISM). Operators of critical infrastructure are subject to the Security of Critical Infrastructure Act 2018 (SOCI Act), as significantly amended in 2024. The Cyber Security Act 2024 adds further obligations relevant to connected devices and incident reporting. For any organisation operating in or providing services to these environments, network security is not discretionary — it is regulated.

---

## Why It Matters

Poor network security is routinely the proximate cause or a significant enabler of major breaches:

- **Lateral movement after initial compromise** is almost always a network security failure. An attacker gains a foothold in one system and traverses the network because segmentation was absent or poorly enforced. NotPetya (2017) spread catastrophically because flat networks allowed a single infection point to reach everything.
- **Unencrypted or weakly encrypted communications** allow interception — credentials, session tokens, and sensitive data are exposed in transit. Downgrade attacks against TLS remain a real threat where legacy protocol versions are still accepted.
- **Misconfigured perimeter devices** create unintended exposure. Overly permissive rules — particularly egress rules — are routinely exploited for command-and-control and data exfiltration. ASD's ACSC has specifically observed malicious actors targeting edge devices (routers, firewalls, VPN concentrators) as they act as enforcement points and hold sensitive traffic.
- **Insufficient network visibility** means attacks run undetected. The Mandiant M-Trends 2024 report noted a global median dwell time of 10 days — organisations with poor telemetry frequently learn of breaches via external notification, not internal detection.
- **Regulatory consequences** are now material. SOCI Act entities face mandatory incident reporting and CIRMP obligations. PSPF entities are assessed annually, and PSPF Release 2024 shifted from a maturity to a compliance reporting model, increasing accountability for CISOs.

## Core Concepts

**Defence in depth, not perimeter reliance.** The traditional model assumed traffic inside the perimeter was trustworthy. That assumption is invalid in hybrid and cloud environments. Effective network security layers controls so that a breach at one layer does not give an attacker uncontested access to everything else.

**Segmentation as a fundamental control.** Dividing the network into zones based on trust level, data sensitivity, and function limits lateral movement. The goal is that a compromised host in one zone cannot freely reach hosts in another. Implemented via VLANs, routing policy, firewalls, or software-defined networking — the mechanism matters less than whether it actually restricts traffic. Under PCI DSS v4.0.1, segmentation is mandatory for reducing cardholder data environment scope and must be tested, not assumed.

**Least privilege applied to network access.** Just as accounts should have minimum permissions, network flows should be restricted to what is actually required. A database server does not need to initiate outbound internet connections. Default-deny outbound is the appropriate starting posture for sensitive zones.

**Encryption of data in transit.** Communications between systems should be encrypted at the transport layer — TLS 1.2 minimum, TLS 1.3 preferred for new implementations. The ISM requires encryption of data in transit for OFFICIAL: Sensitive and above. This applies to internal east-west traffic, not just north-south traffic crossing the perimeter. The ISM now also recognises post-quantum cryptographic algorithms (ML-KEM) for encapsulating encryption session keys, reflecting PSPF 2025 guidance on post-quantum cryptography.

**Zero Trust as an architectural shift.** Zero Trust (formalised in NIST SP 800-207, August 2020) moves security focus from network location to identity and context. Access decisions are made per-session, based on verified identity, device posture, and contextual signals. PSPF Release 2025 now mandates that Australian Government entities develop and maintain a cybersecurity strategy aligned with the ISM and ASD's Guiding Principles to Embed a Zero Trust Culture. Zero Trust is no longer advisory for Commonwealth entities — it is a mandatory direction of travel.

**Network visibility as a prerequisite for detection.** Controls that are not monitored provide limited value. Network telemetry — flow data, DNS queries, proxy logs, IDS/IPS alerts — feeds detection. Under PSPF Direction 003-2024, Australian Government entities using threat intelligence sharing platforms must share cyber threat information with ASD. This requires meaningful network telemetry to exist and be processed in the first place.

**Trust zones and the traffic model:**

```
Internet
    |
    v
[Edge Firewall / WAF / SSE Gateway]
    |
    v
DMZ (public-facing services: web, email, DNS)
    |
    v
[Internal Firewall]
    |
    +---> [User VLAN]        (least-privilege outbound; no lateral access)
    |
    +---> [Server VLAN]      (restricted inbound; no internet-direct egress)
    |
    +---> [OT/IoT Zone]      (air-gapped or strictly filtered; SOCI scope)
    |
    +---> [Management Zone]  (jump hosts, privileged access only)
```

In cloud environments and under the ASD Gateway Security Standard (PSPF 2025), Security Service Edge (SSE) solutions are increasingly positioned at the edge, replacing or supplementing traditional gateway hardware.

## How It Works in Practice

**For Australian Government entities (PSPF scope).** The PSPF Technology domain requires NCEs to maintain a Technology Security Risk Management Plan for all internet-facing systems. This plan must cover: technology lifecycle management; controls to mitigate cyber security vulnerabilities; FOCI risks in technology supply chains; and continuous visibility and monitoring of the technology footprint. Under the ASD Gateway Security Standard (PSPF 2025), entities must authorise gateway systems through the ISM's six-step risk-based approach. SSE solutions are now recognised as an alternative to traditional gateway hardware. Accountability for gateway security cannot be transferred to a third-party provider — it remains with the entity. PSPF Release 2025 also introduces mandatory engagement with ASD's Cyber Security Partnership Program and new obligations for declared Systems of Government Significance (SoGS).

**For SOCI Act entities.** Responsible entities must maintain a CIRMP under an "all hazards" approach that explicitly covers cyber and information security risks, including network-based threats. From August 2024, CIRMPs must align to one of five recognised frameworks: the Essential Eight, NIST Cybersecurity Framework, C2M2, ISO 27001, or the Australian Energy Sector Cyber Security Framework. Mandatory cyber incident reporting to ASD/ACSC applies: incidents with significant impact must be reported within 12 hours; relevant impact within 72 hours. The 2024 amendments consolidated telecommunications security obligations under the SOCI Act (effective April 2025), meaning telecommunications carriers and carriage service providers now operate under a single legislative framework. The CISC can now compel remediation of a seriously deficient CIRMP where there is a material risk to national security or economic stability.

**Architecture and design.** Security architects work with network engineers to define zone models, traffic flows, and trust boundaries before infrastructure is built. Diagrams must reflect actual traffic flows, not aspirational ones. In cloud environments, this includes VPC/VNET design, security group rules, and private endpoint configuration. For government environments at PROTECTED and above, ASD provides specific guidance on Cross Domain Solutions and network separation requirements.

**Firewall and policy management.** Rules require a change control process with an owner, a business justification, and a review cadence. Automated firewall assurance tools identify shadowed, overly permissive, or redundant rules. PSPF Direction 002-2024 requires entities to actively manage vulnerable technologies, which includes network devices running end-of-life firmware.

**Remote access.** Modern remote access is either VPN with MFA enforced, or Zero Trust Network Access (ZTNA). The ISM and PSPF both require authenticated and authorised remote access. The Essential Eight requires phishing-resistant MFA at ML2 — this applies directly to all remote access mechanisms.

**Wireless security.** Enterprise wireless uses WPA3 Enterprise or WPA2 Enterprise with 802.1X. Guest networks are isolated from the corporate network. The ISM includes specific controls for wireless networks, including restrictions on certain wireless configurations at higher classification levels.

**Network monitoring.** Flow data (NetFlow, IPFIX, sFlow) provides broad coverage. IDS/IPS sits at network chokepoints. NDR tools apply behavioural analytics to detect anomalies that signatures miss. DNS and proxy logs are high-value sources — a large proportion of malware command-and-control traffic is visible in DNS queries. ASD's Host-Based Sensor Program and Gateway Sensor Program provide network-level visibility across government. For SOCI entities, equivalent internal monitoring capability is expected to support CIRMP obligations and mandatory incident reporting timelines.

**Roles involved.** Network engineers (configure and maintain infrastructure); security architects (define zone models and policies); SOC analysts (monitor and respond); change/configuration managers (govern network device changes); and — in PSPF/SOCI contexts — the CISO, who is responsible for the cyber security program and carries formal accountability for compliance.

## Common Mistakes and Weaknesses

**Flat networks that were never segmented.** Many organisations have grown organically without effective segmentation. A compromised endpoint has a path to every server. Under SOCI, a flat network allowing lateral movement across a critical infrastructure asset is a CIRMP deficiency — the CISC can now compel remediation.

**Overly permissive egress rules.** Most organisations focus on inbound controls and leave egress as allow-all. Command-and-control traffic, data exfiltration, and lateral movement all exploit unrestricted outbound. Defining and enforcing egress policy is high-value and consistently underimplemented.

**Legacy protocols tolerated for compatibility.** TLS 1.0/1.1, SSLv3, and deprecated cipher suites remain active in many environments because "something still uses them." The ISM explicitly identifies ASD-Approved Cryptographic Algorithms — running deprecated protocols is an ISM gap regardless of the reason. This will become more acute as post-quantum requirements flow through.

**Firewall rule sprawl.** Rules added over years without a decommissioning process. The effective firewall policy differs from the intended policy. This is both a security problem and a compliance problem — it cannot be demonstrated that the policy reflects stated controls.

**FOCI risks in network device procurement ignored.** PSPF Direction 001-2024 requires Commonwealth entities to identify and manage FOCI risks in technology procurement. Network devices — routers, firewalls, switches, VPN concentrators — are squarely in scope. Many organisations have not systematically assessed their network hardware estate for FOCI risk. PSPF Direction 001-2026 specifically required an inventory of Cisco SD-WAN systems and assessment for potential compromise, illustrating how quickly specific device risks can become mandatory actions.

**Treating segmentation as a compliance checkbox.** Segmentation is implemented to satisfy PCI DSS or an audit, but the implementation is superficial — VLANs exist but inter-VLAN routing permits everything. Segmentation must be tested to be trusted. This is explicit in CIS Controls v8.1 and in SOCI CIRMP expectations.

**No network baseline or meaningful monitoring.** Without a traffic baseline, anomalies are invisible. Under PSPF Direction 003-2024, entities must share cyber threat intelligence with ASD — which requires that meaningful network telemetry exists and is being processed. Many organisations deploy monitoring tools but do not operationalise them.

**IoT and OT devices co-mingled with corporate networks.** These devices typically cannot be patched at enterprise cadence, cannot run endpoint agents, and cannot be individually hardened. Under the Cyber Security Act 2024, mandatory security standards for connectable products are being developed — but legacy devices already deployed are not retrospectively captured. Network-level isolation is the primary available control.

## Connections to Other Domains

- **Cyber Architecture (17):** Network security decisions are direct outputs of architectural design. Zone models, trust boundaries, and segmentation strategies are architecture decisions made real in network configuration. ASD's Foundations for Modern Defensible Architecture guides this for government entities.
- **Identity and Access Management (8):** Zero Trust depends on strong identity. Network access decisions are increasingly identity-driven. 802.1X, ZTNA, and conditional access all rely on IAM as the enforcement signal. The PSPF and ISM both tie network access to identity and need-to-know.
- **Cryptography (9):** TLS, IPSec, MACsec, and SSH are cryptographic protocols operationalised in network security. The ISM specifies ASD-Approved Cryptographic Algorithms for data in transit, now including post-quantum standards. Protocol selection and certificate management sit at the intersection of these two domains.
- **Security Operations and Monitoring (12):** Network telemetry is a primary SOC data source. NDR, IDS/IPS, firewall logs, DNS, and proxy data all feed detection. ASD's Gateway Sensor Program and Host-Based Sensor Program are national-scale network monitoring capabilities for government.
- **Incident Management and Business Continuity Planning (13):** Network isolation is a primary containment technique. SOCI mandatory reporting timelines (12 or 72 hours) require rapid detection and assessment, which depends directly on network monitoring capability.
- **Cloud Management (14):** Cloud environments change what "network" means. VPCs, security groups, private endpoints, and cloud-native firewalls require network security principles applied to different constructs. The ASD Gateway Standard explicitly addresses cloud gateway and SSE services.
- **Vendor Management (5):** Third-party connectivity extends the network boundary. PSPF Direction 001-2024 (FOCI risk in procurement) and SOCI supply chain obligations directly govern how third-party network devices and services are acquired and managed.
- **Asset and Change Management (6):** PSPF Direction 002-2024 requires entities to manage vulnerable technologies, including a stocktake of all internet-facing technology assets. Network device inventory, configuration baselines, and change control are prerequisites for compliance.
- **Cyber Testing (10):** Segmentation must be tested. ISM controls require that implemented controls are assessed for effectiveness. Penetration testing and network scanning validate whether segmentation is real, not just configured.
- **Physical Security (20):** Physical access to network infrastructure bypasses logical controls. The PSPF addresses physical security of ICT equipment directly. Network hardware in accessible locations is a physical security problem first.
- **LLM Security (19):** AI and LLM services accessed via the network introduce data egress risks. Network-level controls (egress filtering, DNS monitoring, DLP at the proxy) are the primary technical mechanism for managing what data leaves the organisation through these services. PSPF Directions banning specific applications (DeepSeek, Kaspersky) are enforced at the network layer.
